# WCP360 — Daemon Operation Allowlist — Provisional

## Security invariant

Only explicit, bounded operations are permitted.

Forbidden:
- arbitrary shell;
- arbitrary command strings;
- unrestricted target paths;
- generic sudo proxy;
- generic systemd proxy;
- generic package-manager proxy;
- arbitrary signal number input.

## H3/H3-CM note

The source allowlist historically yielded a count of 43 in one audit, while later enumeration produced 47 distinct IDs. `H3CM-X003` remains open because ACTIVE/SUPERSEDED/ALIAS/DUPLICATE/DEFERRED status is not yet fully reconciled.

The allowlist is therefore preserved as a candidate registry, not a finalized implementation registry.

# Daemon Operation Allowlist

## Core rule

The privileged daemon SHALL expose only explicitly registered operations.

No operation may accept an arbitrary command string.

No operation may accept an unrestricted target path.

No generic shell/sudo/systemd/package-manager proxy is permitted.

## Account operations

### `linux_user.create`
Purpose: create one hosting-system Unix identity.

Inputs:
- account ID;
- canonical Unix username;
- uid/gid strategy;
- home path from approved root;
- shell policy enum.

Restrictions:
- username validated against WCP naming contract;
- home path generated by WCP, not caller supplied;
- shell selected from allowlist;
- no arbitrary supplementary groups.

### `linux_user.lock`
- lock login/session ability;
- preserve files;
- idempotent.

### `linux_user.unlock`
- reverse prior WCP lock only.

### `linux_user.delete`
- destructive;
- requires explicit deletion mode;
- cannot recursively delete arbitrary caller path;
- home path resolved from WCP resource registry.

## Filesystem operations

### `filesystem.directory.create`
Only below registered managed roots.

### `filesystem.ownership.apply`
Targets resolved from managed resource IDs, not arbitrary raw paths.

### `filesystem.permissions.apply`
Mode constrained by policy.
World-writable modes such as `0777` are rejected unless a separately defined exceptional policy exists.

### `filesystem.quota.apply`
Apply account/project quota where supported.

## Web operations

### `nginx_vhost.validate`
- generate candidate config in staging area;
- run bounded validation.

### `nginx_vhost.apply`
- write only WCP-owned vhost target;
- atomic replace;
- preserve previous revision.

### `nginx_vhost.remove`
- remove WCP-owned vhost config only.

### `nginx.reload`
- only if validation already passed for target revision.

## PHP runtime operations

### `php_pool.validate`
### `php_pool.apply`
### `php_pool.remove`
### `php_fpm.reload`

Version/service ID must exist in approved runtime registry.

## Certificate operations

### `certificate.deploy`
- certificate/key source referenced by secret/certificate object ID;
- private key never returned in response;
- target services allowlisted.

### `certificate.remove`
- only from WCP-owned deployment locations.

## Database operations

### `database.create`
### `database.drop`
### `database_user.create`
### `database_user.drop`
### `database_grant.apply`
### `database_grant.revoke`

Database engines and identifiers must be registry-backed.

No arbitrary SQL payload accepted.

## Firewall operations

### `firewall.policy.validate`
### `firewall.policy.apply`
### `firewall.policy.rollback`

Policy input is structured rule data, not raw nftables/iptables command text.

## Service operations

### `service.status`
### `service.reload`
### `service.restart`

`service_id` must exist in the WCP service registry.

Arbitrary systemd unit names are rejected.

## Update operations

### `package.refresh_metadata`
### `package.plan`
### `package.apply_plan`
### `package.hold`
### `package.unhold`

Package operations are based on WCP-generated plans.

No arbitrary package manager argument vector from UI/API.

## Server lifecycle operations

### `server.reboot`
### `server.shutdown`

High impact.
Must require privileged session and job/audit correlation.

## Process operations

### `process.term`
### `process.kill`

Target PID must be resolved to an allowed WCP scope or explicitly privileged system scope.

No arbitrary signal number input.

## Storage operations

### `volume.expand`
### `filesystem.expand`
### `mount.verify`

Shrink is deliberately absent until a safe supported contract is separately defined.

## Cluster/HA operations

### `node.drain`
### `node.uncordon`
### `cluster.failover.prepare`
### `cluster.failover.execute`
### `cluster.failover.verify`

Promotion targets must come from cluster registry.

## Internal rule

Any future daemon capability requires:
1. new operation ID;
2. specification;
3. permission mapping;
4. input schema;
5. filesystem/process/service bounds;
6. job type;
7. audit events;
8. error mapping;
9. idempotency/concurrency declaration.
