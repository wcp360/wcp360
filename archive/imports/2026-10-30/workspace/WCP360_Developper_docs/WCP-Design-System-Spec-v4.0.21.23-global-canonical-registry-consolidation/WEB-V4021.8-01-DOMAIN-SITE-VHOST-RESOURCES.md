# V4.0.21.8 --- Domain, Site & VHost Resource Dictionaries

## Statut

**NORMATIVE B1 --- WEB FAMILY**

### `domain`

`id`, `account_id`, `fqdn_ascii`, `fqdn_display`, `domain_type`,
`status`, `dns_zone_id?`, `primary_site_id?`, `verification_state`,
`created_at`, `version`.

### `site`

`id`, `account_id`, `primary_domain_id`, `document_root_ref`,
`runtime_type`, `runtime_profile_id?`, `webserver_profile_id`,
`tls_policy_id?`, `status`, `created_at`, `version`.

### `domain_binding`

`id`, `site_id`, `domain_id`, `binding_type`, `redirect_policy_id?`,
`canonical`, `status`, `version`.

### `vhost_config`

`id`, `site_id`, `desired_revision`, `observed_revision?`,
`render_hash`, `validation_state`, `apply_state`, `last_applied_at?`,
`version`.

### `redirect_policy`

`id`, `owner_scope`, `source_pattern`, `target_uri`, `status_code`,
`preserve_query`, `https_only`, `version`.

### `custom_directive_set`

`id`, `site_id`, `engine`, `directive_profile`, `validated_payload`,
`validation_state`, `security_class`, `version`.

## Invariants

FQDNs are canonicalized before uniqueness checks. Document roots are
managed path references, never arbitrary privileged paths. A domain may
bind to a site only inside an authorized account scope. Custom
directives are schema/allowlist governed and cannot inject raw shell or
escape managed config boundaries.
