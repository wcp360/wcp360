Host boundaries

One clean operating-system instance.

WCP360 is designed to own the hosting stack it manages. Existing panels, unmanaged web stacks and nested container installs create ambiguous state and should block installation.

  • No cPanel, Plesk, DirectAdmin or another control panel
  • No public database ports required by default
  • Docker-in-Docker and shared OpenVZ hosts are not target environments
  • SELinux or AppArmor policy is detected and included in the plan

Installation methods

Choose the delivery path that matches your environment.

Each method produces the same reviewable plan and first-run wizard. Only artifact delivery changes.

Recommended for evaluation

Guided, interactive and still reviewable.

Download the bootstrap, verify its detached signature, then generate a plan. Nothing is applied until ROOT confirms the final change summary.

  1. Inspect host prerequisites and conflicts.
  2. Select Default or Expert configuration mode.
  3. Review packages, ports, identities and storage changes.
  4. Create a recovery checkpoint and activate.
Preview endpoint · not live
$curl -fsSL https://downloads.wcp360.example/install.sh | sudo bash
Production ruleThe published installer will pin a release manifest and verify it before execution.
Controlled delivery

Pin the exact release and keep the evidence.

Use a versioned archive when change management requires explicit checksums, signatures, SBOM retention and internal mirroring.

  1. Download the archive, checksum, signature and SBOM.
  2. Verify the signer against the published trust policy.
  3. Extract to a staging directory and run preflight.
  4. Archive the final plan with the change record.
Verified archive · preview
wcp360-installer verify wcp360-0.1.0.tar.zst
sudo wcp360-installer plan --mode expert
sudo wcp360-installer apply

Roadmap workflow

Move trust evidence, not hidden network access.

The offline bundle is designed for isolated environments with an approved transfer station and an internal update mirror.

  1. Build the signed bundle for the target architecture.
  2. Transfer through the organization’s media-control process.
  3. Verify signatures and bundle completeness offline.
  4. Install against a local repository and export the audit result.
Offline workflow · specification
wcp360-bundle inspect ./wcp360-offline
sudo wcp360-installer plan --source ./wcp360-offline
sudo wcp360-installer apply --offline
No silent egressRepository, telemetry and licensing destinations remain explicitly disabled or declared.

Transaction model

Know what happens before activation.

Installation is modeled as a staged operation with evidence and recovery at every critical boundary.

01Discover

Host, network, conflicts and capacity.

02Verify

Manifest, signature, checksum and SBOM.

03Plan

Packages, identities, ports and storage.

04Checkpoint

Configuration and recovery state.

05Apply

Atomic service and policy changes.

06Prove

Health gates, audit result and rollback.

First-run wizard

Start quickly or control every decision.

Both modes generate the same final plan. Expert mode exposes the decisions instead of changing the safety model.

DEFAULT / QUICK

Secure production-minded defaults

Conservative quotas, isolated users, local service baseline, automatic security updates and a mandatory backup target.

  • Guided DNS and hostname validation
  • Recommended firewall and brute-force policy
  • Local database and storage profile
  • Review before commit
EXPERT / CUSTOM

Every critical choice exposed

Database, storage, DNS, mail, network, runtime, security, provider and resource settings with inline validation.

  • External providers and cluster topology
  • Custom IP pools and service placement
  • Retention and residency policies
  • Exportable configuration plan

Installer options

Automate the setup without hiding the decisions.

Interactive answers, CLI flags and a versioned configuration file resolve into the same plan. Unknown or conflicting values must stop the run.

Updates and recovery

Update through a staged transaction — not a blind package upgrade.

Every update resolves compatibility, creates a checkpoint, stages artifacts, runs health gates and keeps the previous release available until promotion succeeds.
