The reason

The problem is not missing buttons. It is missing structure.

Traditional panels proved that one interface can operate a hosting server. WCP360 keeps that operational ambition, then rebuilds the model around explicit authority, durable jobs and recoverable change.

01
LEGACY PATTERN

Roles separated mostly by menus

Hiding a screen is not an authorization boundary, and a convenience switch must never become privilege escalation.

WCP360 DIRECTIONCapability, tenant and ownership checks are enforced server-side.
02
LEGACY PATTERN

A click is treated as success

Long-running infrastructure work can partially fail even when the interface has already shown a green notification.

WCP360 DIRECTIONEvery mutation becomes a planned, durable and verifiable operation.
03
LEGACY PATTERN

Add-ons become hidden core dependencies

Optional software can expand until the platform cannot update, recover or even start without it.

WCP360 DIRECTIONExtensions declare permissions, failure behavior and deterministic removal.

Non-negotiable principles

Power is useful only when it stays understandable.

Automation may be advanced. Its authority, impact, evidence and recovery path must remain clear to the operator.

01

Autonomy before convenience

Authentication, hosting and recovery must continue locally when licensing, catalogue or vendor systems are unreachable.

Offline-safe baseline
02

Privilege must be explicit

Actors, extensions and workloads receive narrow capabilities instead of ambient ROOT access.

Least privilege by contract
03

Extensions must fail safely

A failed plugin withdraws its routes and jobs without taking the hosting baseline down with it.

Contained failure domains
04

Operations need evidence

Intent, authorization, execution, verification and recovery information belong to one auditable chain.

Proof, not optimistic status

Customer installationThe hosting baseline remains usable when every optional extension and private service is offline.
PUBLIC RELEASE RULE

Build from an allowlist, never from an exclusion list.

Every public archive is assembled from explicitly approved components, scanned for secrets, checked against its SBOM and signed before publication.

Honest project status

Ambition is not the same as availability.

WCP360 currently demonstrates information architecture, functional coverage, lifecycle design and trust boundaries. Production readiness requires working agents, signed artifacts, installation tests, migrations and recovery evidence.
