# FrankenPHP classic and Worker service profiles

Owner: [Hosting](../../../src/Module/Hosting/README.md). Status: external experimental plan/preview sources; no installed or production-qualified provider in this directory.

The [application-server guide](../../../../documentation/development/APPLICATION-SERVERS.md) defines the global default, per-site choice, compatibility acknowledgement, isolation requirements and platform boundaries. The current candidate default remains Nginx/PHP-FPM. The [adopted strategy](../../../src/Module/Hosting/WEB-SERVER-STRATEGY.md) targets Nginx -> Apache event -> FPM for new general-purpose installations after explicit implementation; existing assignments remain unchanged.

The executable candidate keeps the actual templates together with their Go renderer under [agents/wcpd/candidate/planner/templates](../../../agents/wcpd/candidate/planner/templates): Caddyfile.tmpl, nginx-frankenphp.conf.tmpl and frankenphp.service.tmpl. Do not copy them here or create a second renderer. The planner emits inert text only. Separate Modern Worker templates and the [classic application family](../../../agents/wcpd/candidate/planner/templates/applications) remain in the same canonical Go source tree. Classic does not use a persistent application worker; Worker requires its own explicit application compatibility and state-reset/recycling evidence. Embedded Caddy is part of the FrankenPHP instance, not another required daemon.

Independent customers require isolated unprivileged process/Unix identities, private listeners, filesystem scope and resource budgets. The existing edge-proxied Worker uses a per-site Unix socket with Caddy automatic HTTPS/admin access disabled; direct previews have a distinct unreserved loopback topology. None reserves public ports or grants TLS/activation authority. wcpd/wcp-privd remain separate system-operation components.

Existing Debian candidate probes do not qualify every new application/classic/Modern profile. Core targets are Debian 12/13 and Ubuntu 22.04/24.04/26.04 LTS; each provider/package/extension combination needs its own native evidence. AlmaLinux/SELinux is not added to that matrix here. Native install, live switching, health/drain, data-aware recovery and full host qualification remain open. Follow the [web-server roadmap](../../../src/Module/Hosting/WEB-SERVER-ROADMAP.md), [service index](../README.md), [resources](../../README.md) and [Core structure](../../../STRUCTURE.md).
