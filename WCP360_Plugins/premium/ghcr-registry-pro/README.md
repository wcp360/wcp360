# GitHub Container Registry connector

This is an optional premium connector proposal, not an implemented or installable package. Its current state is **design**, **not installable**, with the source distribution model **undecided**.

Prepare explicit package and digest references from GitHub Container Registry for reviewed application deployment.

## Core boundary

Package visibility and registry authentication do not authorize privileged containers, host mounts or automatic execution. This is a design-only connector proposal. Essential hosting, current actor and tenant authorization, native service drivers and recovery remain in the free Core. No production interface, publisher trust, installation or effectful capability is established by this metadata.

## Intended scope and evidence

1. Admit selected owners and package namespaces; resolve deployment inputs to immutable digests before approval.
2. Qualify pull credentials, visibility changes and provenance policy with least privilege and secret-reference storage.
3. Exercise unavailable artifacts, moved tags and revoked access without silently replacing an approved artifact or broadening runtime permissions.

The complete [acceptance record](docs/ACCEPTANCE.md) defines evidence still required. No checks are marked complete, and no SDK/provider version, target compatibility, release artifact or production entitlement is selected.
